# v0.1 历史与 CLI 协议

状态：开发预览。记录 schema_version 和 CLI protocol_version 独立版本化，当前均为 1。发生不兼容变更时应增加对应版本，而非静默改变旧记录语义。

## 记录

Case 包含 schema_version、id、title、created_at。Entry 包含 schema_version、id、case_id、kind、content、references、author、created_at。Reference 包含 target_id、relation。

Case、Entry ID 由 Core 生成 UUID v4；所有查询和引用要求小写、带连字符的规范 UUID。created_at 由 Core 生成 RFC 3339 UTC 时间，不能用它决定历史顺序。

新建 Case 请求只有 title。新建 Entry 请求包含 case_id、kind、content、author，以及可省略并默认为空数组的 references。未知字段、调用者提供的 id、created_at 或 schema_version 一律拒绝。创建成功返回持久化后的完整记录。

title 为非空白字符串，至多 512 UTF-8 字节；kind 和 relation 至多 128 字节；author 至多 256 字节。content 必须非空白。每个 Entry 至多 128 个引用；相同 target_id 与 relation 的组合不能重复。输入和值保留原样，不自动 trim 或规范化。

单个 stdin JSON 请求最多 1,048,576 字节。Core 生成的每条 Case、Entry 在紧凑 JSON 序列化后也不得超过该值，包括自动生成字段及 JSON 转义开销。Schema 的 maxLength 按 Unicode 字符计数，UTF-8 字节限制额外由 Core 强制执行。

## 历史语义

- Case 和 Entry 一旦提交，不能通过公共 API 修改或删除。
- 修订是一条引用旧 Entry 的新记录，惯用 relation 为 supersedes；它不会隐藏或删除旧记录。
- 所有引用目标必须先于当前 Entry 存在，且属于同一 Case。因此首版不支持跨 Case 引用、前向引用和引用环。
- kind 和 relation 是开放字符串。系统不推断真伪、权限、验证状态或状态转换；supersedes 也不触发自动替换。
- author 是署名，不是身份验证。
- 每次创建或追加都是一个完整事务。任一验证、外键或存储写入失败都会回滚这次写入。
- 由 SQLite 内部递增 seq 决定提交后的追加顺序；seq 不属于开放 Entry 记录。
- Repository 不接受外部自定义新记录 ID；数据库 UNIQUE 约束仍用于防止重复 ID。

## 查询

CLI 提供 case create/get/history、entry append/get。写请求通过 stdin 接收单个 JSON 对象；case create 也支持 --title。

history 返回 `{ "entries": [...], "next_cursor": "123" | null }`。
limit 默认 100，范围 1..=1000。after 是之前返回的十进制正整数游标；游标仅适用于原数据库和原 Case。结果按 seq 升序返回，只有存在后续记录时才给出 next_cursor。

分页不是冻结的快照；后续页可以包括分页开始后新提交的记录。最后一页返回 null，持续追踪新历史的接口留待后续设计。

查找不存在的 Case 或 Entry，CLI 返回 not_found。Repository 单记录 get 返回 None；不存在 Case 的 history 返回错误，以区别空历史。

## 输出与错误

成功：stdout 一行 JSON `{"protocol_version":1,"data":...}`，退出码 0。

失败：stderr 一行 JSON `{"protocol_version":1,"error":{"code":"...","message":"..."}}`，stdout 为空。

错误 code：invalid_input、not_found、invalid_reference、unsupported_schema、storage_error。退出码 1。命令行解析失败使用 invalid_arguments，退出码 2。message 用于诊断，集成方应依赖 code。help/version 输出普通文本。

数据库路径是显式的 CLI 配置，不是记录字段，也不能通过记录 JSON 选择任意内部文件。CLI 以调用进程的文件权限运行，不提供沙箱隔离。

## SQLite 实现

使用打包的 SQLite、foreign_keys=ON、recursive_triggers=ON、synchronous=FULL、5 秒 busy timeout。schema 初始化和版本设置在同一个事务中进行。user_version=1；未知版本拒绝打开，不自动降级。尚无升级旧 schema、导入或导出的命令。

cases、entries、entry_references 使用主键、唯一约束和外键。UPDATE/DELETE 触发器拒绝意外覆盖；拥有文件写权限的人可以删除触发器，所以它们不是抗恶意篡改措施。

SQLite 的事务与持久化依赖底层操作系统和文件系统正确工作。本版测试模拟事务内写入失败及重开连接；尚未进行断电或硬件故障注入测试。
